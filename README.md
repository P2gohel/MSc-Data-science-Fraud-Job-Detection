# Detecting Fraudulent Job Postings: A Comparative Machine Learning Approach


## Project Overview

This project develops an automated machine learning system for detecting fraudulent job postings.
Two classifiers — Logistic Regression and Support Vector Machine (SVM) — are compared using
TF-IDF text features, with a feedforward neural network as an additional reference point. The output is an interpretable fraud-likelihood score (probability),
not a binary label, so end users can make informed decisions.

## Dataset

[Real or Fake: Fake Job Posting Prediction (Kaggle, 2020)](https://www.kaggle.com/datasets/shivamb/real-or-fake-fake-jobposting-prediction)

- 17,880 job postings
- 866 fraudulent (4.84%) — heavy class imbalance
- 18 columns: text fields (title, description, requirements, benefits)
  and structured fields (has_company_logo, telecommuting, employment_type)

## Methodology

1. **EDA** — explore class balance, feature distributions and text patterns
2. **Preprocessing** — text cleaning, lemmatisation, missingness flags as features
3. **Train/test split** — stratified 80/20, performed before any feature fitting so the test set is fully held out
4. **Feature Engineering** — TF-IDF fitted on the training text only, combined with 6 binary metadata features
5. **Modelling** — Logistic Regression vs SVM, with a neural network as reference
6. **Imbalance Handling** — compare `class_weight='balanced'` and SMOTE, applied to training data only
7. **Evaluation** — accuracy, precision, recall, F1, AUC-ROC, confusion matrices, 5-fold cross validation
8. **Explainability** — SHAP word-level explanations on the chosen model
9. **Prototype** — interactive interface showing fraud probability and key influencing words


## Results

| Model | Accuracy % | Fraud Precision % | Fraud Recall % | Fraud F1 % | AUC-ROC |
|---|---|---|---|---|---|
| LR — Baseline | 97.29 | 98.72 | 44.51 | 61.35 | 0.9812 |
| LR — Class Weighting | 95.83 | 54.11 | 91.33 | 67.96 | 0.9886 |
| LR — SMOTE | 97.15 | 64.85 | 89.60 | 75.24 | 0.9898 |
| SVM — Baseline | 98.80 | 96.43 | 78.03 | 86.26 | 0.9897 |
| SVM — Class Weighting | 98.71 | 93.79 | 78.61 | 85.53 | 0.9900 |
| SVM — SMOTE | 98.66 | 95.62 | 75.72 | 84.52 | 0.9877 |
| ANN | 98.63 | 90.26 | 80.35 | 85.02 | 0.9919 |

5-fold cross validation: LR class weighted 0.665 (± 0.017), SVM baseline 0.829 (± 0.026)

### Key Findings

- **Severe class imbalance** — 4.84% fraud (866 of 17,880), so accuracy alone is not a usable measure
- **Missing fields signal fraud** — postings without a company profile have a 17.7% fraud rate against 1.9% where present. Turned into three engineered features
- **`has_company_logo` is the strongest metadata signal** — postings without a logo show around eight times the fraud rate
- **Accuracy is misleading** — baseline LR scored 97.29% accuracy but caught only 44.51% of fraud
- **Imbalance handling is classifier-dependent** — class weighting lifted LR recall from 44.51% to 91.33%, but did nothing for SVM.
- **SVM baseline is the strongest classifier** — F1 86.26 with only 5 false alarms, without any imbalance handling
- **LR with class weighting was deployed** — highest recall at 91.33%, missing only 15 of 173, and its linear form allows exact SHAP explanations. SVM is reported as the performance ceiling
- **SHAP validates the engineered features** — `has_company_logo` and `has_company_profile` outweigh any individual word as legitimacy signals
